# 商家端微信小程序 · 开发预览

这是用户确认“一期先做开发版”后的**独立本地预览阶段**，可体验手机号匹配、多商户切换、每日营业额/订单数与图片凭证、草稿提交、模拟缴费记录、报修。

**尚未对接 ERP 后台。** 数据只存在微信开发者工具/当前设备中；不发送网络请求，不验证真实手机号，不调用微信支付，不产生真实收款，不向物业派单。不可用于生产或提交为正式可交易小程序。`lib/store.js` 是显式开发数据源，不是生产 API 实现。

## 打开

1. 安装并登录微信开发者工具。
2. 导入本目录 `miniapp/`，使用测试号/游客体验（配置中为 `touristappid`），小程序目录为 `./`，无需 npm 构建。
3. 编译后使用页面预填的演示手机号 `13800000001`。对应“海源茶舍（测试）”和“海源文创（测试）”。
4. 首页切换商户，分别体验报送、账单和报修；“我的 → 重置演示数据”恢复初始状态。

未安装或未登录开发者工具时，不能凭 Node 测试证明原生 WXML 编译、图片 API、暗色主题和真机布局正确。当前只完成逻辑和页面控制器自动化验证，开发者工具/真机验收待执行。

## 行为边界

- 仅管理员预设的演示授权手机号可进入；未知号码拒绝。真实版须由服务器使用微信手机号授权 code 换取号码，客户端不能提交自称已验证的手机号。
- 同一手机号可管理多个商户；每次业务操作重新检查商户授权。生产版另需 ERP 端的授权手机号维护与立即撤销机制，不能直接拿一般联系人号码当授权。
- 营业额精确到分、订单数为非负整数；每天每商户一份报送。草稿可编辑，提交后不能修改。零营业额有效。
- 模拟缴费只付整张账单剩余金额，稳定请求键避免重复。所有金额、成功提示均明确标识为模拟。
- 选择的图片通过本地 `saveFile` 保存，不上传后台。未保存表单离开前提示放弃；仅清理新附件，已保存记录附件保留。重置时清理该预览记录引用的附件。
- 未保存的输入保存在页面内存，退出小程序进程会丢失。需要保留报送时点击“保存草稿”。不得输入真实个人信息或真实证照。
- 样例授权和本地状态都可被调试器修改，因此它不是安全边界演示或真实身份认证。隔离用例只验证未来服务端实现应遵循的业务规则。

## 正式接入的后续开发

本仓库现有营收报送 `server/hyl/`、账单/核销 `server/billing/`、收银 `server/cashier/`、报修 `server/repairs/` 应作为唯一业务账本。不能将这里的模拟账本复制到生产。

1. 新增商户授权手机号与多成员关联，保留现有 `userId` 兼容；后台维护、审计与撤权，所有读取/写入/附件均校验商户范围。
2. 在已有 Better Auth 中接入微信 `code2Session` 和手机号 code 验证，绑定 AppID+OpenID，复用 bearer 会话；不自造 JWT、不按未经验证的号码关联。
3. 建立商家专用 API，复用原业务审批、幂等和附件权限；订单数字段新增迁移，不改已执行历史迁移。迁移和接口需真实数据库测试。
4. 物业作为统一收款方，微信支付 APIv3 下单；金额由服务器按最新账单计算。验签解密回调并校验 AppID、商户号、订单号、币种和金额；重复回调幂等，未知结果主动查单，关闭订单后才能释放支付占用。客户端支付成功回调不能直接核销。
5. 在同一资金事务内登记收款、核销和支付回调处理结果；并发线下收款需共享账单锁/占用规则，防止重复收款。
6. 配置真实 AppID/Secret、物业商户号、支付私钥/证书或公钥、APIv3 密钥、HTTPS 域名与回调；配置隐私声明、上传/请求域名并做真实测试员工和测试账单联调。

没有凭证不妨碍上述服务端开发；这些接入代码当前尚未实现，不能将本预览视为整个商家端项目已交付。

## 自动化验证

在仓库根目录运行：

```sh
NODE_OPTIONS=--import=tsx node node_modules/vitest/vitest.mjs run tests/miniapp
```

覆盖多商户授权、撤权、伪造跨商户 ID、零报送、状态与版本校验、日期和金额验证、重复付款、存储失败、草稿离开确认、附件卸载清理。无需真实微信账号或财务数据。
