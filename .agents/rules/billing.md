# 计费与账单

应用代码在 `server/billing/`、`server/routes/billing.ts` 和 `client/pages/billing/`；业务说明及演示记录见 [计费账单与收款核销](../../docs/计费账单与收款核销.md)。

- 租金渠道来自版本化的 `hylBillingConfigs`：旧合同默认经营结算扣租，显式账单渠道令新经营结算快照的扣租为0。不得改写历史结算。费率只在未来未出账周期边界修改，启停费用按版本有效区间检查经营费用冲突。
- 正额及零额账单都保存明细快照。租金和物业按当月实际天数折算，水电按读数消费计算，不二次折算。签约面积来自合同资产快照。
- 押金抵扣仍是 `hylLeaseEntries` 的deduct流水，`payload.sourceType='bill'`、`sourceId=billId`。押金冲销必须同事务重算账单余额。收款、核销、退款及冲销保留不可变流水，作废不删除参考号。
- 所有写操作先取得合同动作及记录策略，再进入数据库事务，先执行已有merchant CAS锁。不要在SQLite事务中通过根连接重新解析权限。账单和收款缓存余额在同事务从有效流水重算，供SQL分页、筛选、排序使用；不能只改缓存数字。
- 子表读取和写入均派生自对应动作的合同记录范围；账单读取不意味着有押金或收款明细读取权。页面授权不是API授权，跨来源核销逐目标检查，同一收款仅属于一个合同。
- 退租归档除余额外还检查所有有效费用、预期表号的期间覆盖。零用量需要保留读数及凭证并发布确认，不能靠没有账单充当零费用。临时抄表缺口确认不豁免最终覆盖。纯收租无经营来源且固定经营费为0时，完整租金账单覆盖可替代空经营结算；其他合同仍须完成经营结算。
- 财务动作重试的requestId对应原意图；未知网络结果重试保留id，409显式加载并复核后才创建新意图。禁止静默覆盖版本或删除原始流水。
- 详情模块复用于父子路由时，使用`useResolvedPath('.')`识别当前模块自己的路径，不用全局location判断记录类型，否则下层收款会令上层账单变成收款并崩溃。生成表单打开配置时使用带合同id的子路径，避免改掉父级筛选。
- 新权限只注册能力，不覆盖既有岗位配置；其他岗位由权限管理明确分配。仅演示线下台账，不调用真实支付、银行、发票、设备或定时扣款。
