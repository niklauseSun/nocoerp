# Operation logs

`/operationLogs` lives under 系统管理. Both page and API require the authorization snapshot's `unrestricted` flag; no grant or assignment is added for ordinary users. APIs are read-only list/detail; the collection is not exposed as generic CRUD. No deletion or editing interface.

`server/app.ts` registers `operationLogMiddleware` through public `addHttpMiddleware` before startup. This deliberate entry-point customization is required because providers run after routes become immutable and application API contributions cannot wrap earlier plugin/forwarded management APIs. Preserve middleware order after session/i18n and before route mounting when upgrading. The logger resolves identity with the public authentication service and never replaces the owning endpoint's authentication, origin checks or business authorization.

`server/operation-logs/operations.ts` is an explicit method/path allowlist derived from authenticated OpenAPI. When adding business or administration mutations, add their documented route; keep previews, subject resolution, access inspectors, authentication and page viewing excluded. Fixed route templates are stored, never raw URLs, query strings, request bodies, headers, response bodies, error messages, passwords or tokens. Only a closed vocabulary of validated action names, strict scalar target identifiers, canonical error status and operator identity are projected. Background jobs and old module histories are not backfilled.

Each matching HTTP attempt gets a new immutable UUID row after the endpoint returns, including rejected/failed attempts. These request logs complement module transactional histories and financial ledgers. They do not replace them: an audit insert failure writes a payload-free diagnostic with its proposed log ID and preserves the business response, because the business transaction may already be committed. Review operationLogs diagnostics if persistence fails.

List filters/pagination/order execute on the server; date filters use inclusive Asia/Shanghai days. Client query keys include session user and authorization revision and never show previous identity's data. Detail is a route drawer preserving list filters. Tests in `tests/operation-logs/` and `tests/components/operation-logs.test.tsx` use temporary data only.

Failed-path targets only retain UUID/numeric IDs; permission-set keys are retained only after a successful authoritative operation. Assignment IDs take precedence over role keys. Caller request IDs are kept only when UUID-shaped; other values are replaced with a generated UUID. Error status is checked against public apiErrorStatusCodes. The fixed action vocabulary includes all documented path/body action enums (notably deposit application, receipt allocation/reversal and lease closure); keep the bilingual action copy aligned. The explicit manifest also covers inspection scheduler enable/disable and inbox read-state mutations.

The date range uses one Calendar/Popover with presets, two months on wide screens, one on phones, and localized invalid-range feedback. Reject malformed/impossible URL dates before calendar formatting. Refresh preserves existing rows within the same identity/revision/path only, with loading on the refresh control; a changed identity/revision clears the projection. These are request-level traces, not before/after permission or financial ledger diffs.
