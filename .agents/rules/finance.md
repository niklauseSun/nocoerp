# 财务报表

- 代码在 `server/finance/`、`server/routes/finance.ts`、`client/pages/financial-reports/`；口径、演示记录和复跑方式见 [财务报表与资金台账核对](../../docs/财务报表与资金台账核对.md)。
- 服务只读原始业务台账，不写第二套资金流水；统一收银通过收款／押金原账进入报表。`server/cashier/reports.ts` 的 `collectCashEvents` 与日结共用原始现金事件提取，不把日结快照、核销、抵扣、结转、开票或采购计提重复记现金。
- 金额使用整数分字符串和 BigInt。现金及押金期间变动按上海登记日，冲销按自身登记时间反向入账。期初／期末累计现金净额不是银行余额。应收应付、当前押金是当前事务快照，不能按今天的单据状态伪造历史时点余额。
- AR 包括已发布账单及已确认的合同收费／负结算补缴；AP 包括已确认商户结算及采购验收计提。预收未核销款与押金分开，不相互抵消。重算余额与业务缓存比较，异常负数和差额不能静默截为0。
- `hyl.finance/read` 具有 contracts 与 assets 两个范围；还必须消耗合同、商户、结算、资产和采购原始业务权限。所有合同来源取 read/billingRead/receiptRead/depositRead/cashierReconcileRead/splitRead 交集；采购同时守住供应商与关联工单范围；结算来源的分账付款仍检查原结算。无必要操作403、隐藏或不存在的来源404，不泄露排除数量和名称。新增权限不自动追加给既有角色。
- 所有策略在事务外解析，事务内只用传入连接读取同一快照。所有聚合先穷尽权限内来源，再筛选／排序／分页。单项目只含单项目合同，跨项目及无绑定合同不做任意分摊，只在全授权范围展示。
- Demo 是显式的本地 `app finance-demo` CLI，帮助文件 `cli/lib/finance-demo.ts`；拒绝生产运行，每次创建标记的独立项目，仅原业务服务登记模拟操作。不是 seed，不创建新账号，不授予权限，不发起真实支付。
- 相关测试在 `tests/finance/`；共享现金提取变动还跑 `tests/cashier/workflow.test.ts`。不需要新表或迁移。UI 保持原始权限错误处理、来源抽屉父 URL 和筛选，刷新不得显示旧权限／旧项目的缓存金额。
