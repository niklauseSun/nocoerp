# 项目与资产管理（一期）

- 页面位于 `client/pages/assets/`，入口 `/assets`，资源 `hyl.assets`，页面权限 `hyl-assets`；业务服务在 `server/providers/assets.ts`，附件服务在 `server/providers/asset-files.ts`。不创建插件、不使用通用公开附件路径。
- `202610150004_assets` 为独立迁移，创建资产、追加历史、商户绑定、合同关联快照、私有附件及清理凭据、权限初始化标记。已执行迁移不可修改；新增修正迁移。没有示例数据，也不自动迁移旧商户的铺位自由文本。
- 层级：项目→街区→楼栋→铺位/摊位；铺位/摊位也可直接属于街区。类型创建后不可变。有子节点不能移动；叶节点允许调整父级。无物理删除入口，停用需下级均停用且没有当前/未来绑定或合同。
- 所有资产/绑定/合同关联写入都在原业务事务中按项目ID排序锁项目行。锁后重读并检查projectId，跨项目移动与绑定竞争返回版本冲突。先解析所有权限，再开事务；事务中使用传入connection，避免SQLite单连接死锁。
- 商户绑定要求商户write及资产write。允许共享；同商户同资产不能日期重叠。登记面积不计算共享剩余可租面积。结束绑定保留历史且不能截断关联合同覆盖期间。
- 合同 `assetIds` 可选，兼容旧合同。保存重新检查商户绑定覆盖日期；新增关联取得资产摘要快照，保留未变化关联原快照。已有结算使用的合同沿用原禁止修改规则。商户自己的详情只返回已绑定资产摘要，合同详情只返回自身签约快照；资产卡片关联列表分别应用商户/合同read权限。
- 附件使用 File Repository `assetFiles`，PDF/JPEG/PNG最大10MB；保存资产后上传，类别为图纸/照片/权属证明。通过 `/uploads/assets/*` 私有授权后stream，临时文件只允许上传者且有资产write权限访问，关联后资产read范围可读。图纸不加营业执照水印。
- 上传带uploadId和SHA256支持响应丢失恢复；关联fileId必须属于同一资产及上传者。link和cleanup通过项目锁互斥；清理先写持久凭据，物理删除失败可重试。已关联文件不提供删除，保留审计。待关联列表有明确恢复/清理入口。
- 默认权限通过公共permissionSets服务一次性追加财务read/write与只读管理read，不分配新用户。`hylAssetSetup.permissions-v1`防止重启覆盖后续管理员修改。
- UI草稿仅按session.user.id分区保存在内存；未提交附件可由服务端恢复，不写浏览器持久存储。
- 验证：`tests/assets/`覆盖迁移up/down、真实SQLite API权限/约束/附件及组件行为；运行server测试需`NODE_OPTIONS=--import=tsx`。合同/结算受影响时同时运行`tests/hyl/workflow.test.ts`。

- 使用情况按 Asia/Shanghai 业务日期判断，结束日包含当天。面积排序一期在权限范围内按精确小数排序；大规模台账需将面积排序及使用标记查询进一步下推到数据库。
- 资产卡片中的关联商户/合同采用只读摘要，子页面链接保留搜索参数，避免跨模块跳转丢失来源。上级名称通过独立read权限查询。桌面层级树预留16rem以兼顾多级名称和右侧列表，窄屏改为纵向排列；上级不在当前授权/已加载页中的节点仍可见，铺位/摊位直接打开卡片。
- 待关联附件只向上传者返回uploadId，客户端在会话草稿记录本表单的上传意图和文件ID。自动取消/保存清理只处理本表单已知或恢复选中的文件，避免误删另一个标签的未完成上传；无法确定归属的待处理文件保留手工恢复/清理入口。
