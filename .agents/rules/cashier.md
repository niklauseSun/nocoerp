# 收费与统一收银

入口为 `server/cashier/`、`server/routes/cashier.ts`、`client/pages/cashier/`；演示说明见 [收费与统一收银流程](../../docs/收费与统一收银流程.md)。

- 收银单编排同一商户多合同收款，不是第二本资金账。每笔支付显式分合同，产生既有 hylReceipts；核销沿用 hylReceiptEntries，押金抵扣沿用租赁押金流水。
- hylCashierMembers 关联所有来源合同。任一来源不在动作/读取范围内则整单不可见，不显示部分金额或泄漏总数。页面权限不能替代 API 逐合同检查。新能力不自动扩大岗位授权。
- 写入先解析所有策略，再按商户锁进入同一事务。BillingService.transactionScope 仅供内部校验后的 actor/merchant 调用，不能通过公开请求传递，也不能在 SQLite 事务内用根连接重新解析权限。
- 草稿不预占资金。payload.input 只保存 checkoutSchema 业务字段，不能混入 requestId/expectedVersion/UI标签。post 重新校验来源版本，原子写入收款、核销、押金抵扣及幂等结果。
- 外部参考号通过 hylCashierReferences 与原收款/押金入口共同按商户校验；冲销不释放参考号。逐合同内部参考号独立，原支付参考号保留在收银快照。
- 已核销款部分退款先冲销全部有效核销，再重建保留部分，最后退款，同一事务完成。退款冲销恢复未核销余额，不自动核销。原收款入口操作必须刷新 refreshOrders/refreshRefunds；部分退款来源已冲销时仅处理剩余有效来源。
- 日结按 Asia/Shanghai 的 createdAt 登记日汇总，凭证日期单列。仅统计原始收款和资金事件一次；核销、押金抵扣、续租结转不产生资金流。押金单列类别，经营返款另行管理。
- 净收=实收−退款登记额（冲销前）+更正净额。核对保留不可变全日快照，sourceHash 变化要求重新预览；后续补录创建替代版本，各版本不能叠加。现金差额必须说明，不自动调账、不冻结记账期、不代表银行匹配。
- 结果未知时保持同一 requestId 重试；409 明确加载新版本和重新预览后再创建新意图。禁止删除财务流水来修正。
- 详情以 useResolvedPath('.') 判定模块类型，避免被下层 URL 改变。来源使用有限子路由，遇到祖先返回原祖先；不得无限追加 bill/receipt/order 循环。合同来源是只读叶节点，履约操作在原合同页面。
- 仅登记线下凭证，不接入真实支付、发票或自动分账。已有计费、读数覆盖和退租结清约束均适用。
