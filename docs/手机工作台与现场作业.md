# 手机工作台与现场作业

手机浏览器登录后，首页进入 `/workbench`。仍使用原有会话、业务接口、角色和项目数据范围；没有另建手机账号、同步库或扩大授权。桌面首页继续是经营看板，侧栏也可进入工作台。

## 手机入口

- 工作台：常用功能入口，最多五条个人业务待办、五条待本人审批；总数来自原接口，业务待办数量不等于未读消息数量。
- 消息待办：站内消息沿用官方收件箱的已读未读和实时刷新，业务待办可进入来源记录处理。提醒订阅仍由个人消息设置控制。
- 审批：筛选本人待审、本人提交及获授权请求，查看多级审批进度、审批意见和历史，并使用原有通过、驳回操作。
- 报修：报修登记、派单、开始处理、进度、验收及关闭使用原流程和原资产/商户/合同选择器。
- 巡检：计划、任务执行、异常上报、整改复查与报修关联沿用原有执行人限制和任务快照。
- 抄表：水电表、读数草稿、提交审核、用量出账使用原流程；读数保留原小数精度。选择出账仍受状态、单合同和最多五十条等原规则限制。

工作台的受保护入口同时检查原页面权限与原业务读取权限。没有权限的入口隐藏；审批摘要给出授权指引，不请求无权数据。服务端始终负责来源和操作权限。账号或授权版本变化后，不复用其他账号或旧权限的查询结果。

## 布局和操作

小于 768px 时，主要列表以编号链接、状态和带字段名的卡片展示，保持原查询、筛选、服务端排序和精确分页；桌面继续展示原表格。卡片直接复用原表格的单元格与操作子树，避免两套按钮资格判断。抄表有选择列时，编号仍为卡片标题。

底部是工作台、业务待办、站内消息和全部功能。全部功能打开原权限过滤菜单。底部导航占独立布局行，不覆盖滚动内容和表单按钮。手机的字段字号、触控区域、长文字、详情字段和表单按钮布局已适配；对话框继续使用原路由、离开保护与提交中锁定。工作台的待办与审批详情是子路由，返回后保留工作台及查询条件。

## 运行与验证

入口示例：运行中的开发服务打印的 Local 地址加 `workbench`。本次为 `http://127.0.0.1:13000/main/workbench`。该回环地址仅供本机访问；真机使用需要能访问开发服务的地址或部署域名，不能在手机上直接使用电脑的 `127.0.0.1`。

组件测试在 `tests/mobile/`，原业务及外项目隔离测试继续运行在各模块测试目录。浏览器检查使用当前管理员和现有演示数据；窄屏检查使用同源页面嵌入的真实 375/390px iframe 视口，并非物理手机。临时检查页面在交付前删除，截图保留在 `storage/ui-workflow/mobile-workbench/screenshots/`。

不包含原生 App、微信小程序、离线写入、系统推送或新的相机采集能力。弱网失败仍保留输入，按原页面的幂等重试与结果未知提示处理。真实 iOS/Android 键盘、刘海安全区域和系统输入法仍需真机验证；不能把浏览器窄屏截图等同于真机验收。
