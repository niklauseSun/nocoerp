# 支付即开票流程

支持模拟电子普通票、自动/人工蓝票、合并开票、部分/全额红冲及更正后重开。票面永久标记“模拟发票，不具备税务效力”；本次演示税率0%。

## 办理方式

1. 在“支付即开票 → 开票配置”选择合同，确认购销方、费类税项和演示税率，按需启用自动模拟开票。保存新增版本，不修改历史票。
2. 收款核销或押金实际抵扣到已发布账单后生成开票任务。资料齐全且启用自动时出蓝票，否则在任务页预览并确认。相同商户及兼容购销方、费用映射的来源可合并开票。
3. 退款导致有效已付下降时显示待红冲。打开原蓝票，选择退款原因和逐行金额、填写依据，预览后确认，可分次红冲。红冲只更正票据，不再次退款。
4. 补款重新核销后恢复可开额度，启用自动时再次出蓝票。退款冲销只恢复未核销余额，必须重新核销才恢复额度；原红票永久保留。
5. 抬头错误按“更正”红冲后，保存新的开票配置并重新开蓝票。已知失败只记失败记录，额度不变；结果未知保留同一请求重试。

已执行真实SQLite迁移up/down、整数分摊与红冲税额测试、事务队列清理与合并刷新测试、HTTP完整流程、跨合同合并票权限测试和页面交互测试。相关计费、收银、分账及租赁回归通过。浏览器核对了中文列表、来源余额、蓝红票链、红冲预览和失败确认。其余运行验收范围见最终交付说明。

本轮针对开票及受影响模块的回归共27个文件、65项测试通过，客户端与服务端类型检查、受影响文件的lint和格式检查通过。独立验收发现的逐行预览、配置列表、表单校验、受限明细、主操作、历史快照展示、成功提示、API响应文档和空态文案已修复并自查。

浏览器使用现有中文、浅色会话；英文、深色、其他主题预设和原生输入法中间态未实测，未改变用户外观设置。实际断网后的未知结果重试、每一种本地入口组合及每个子表第二页未逐一人工走查，已有组件/接口测试覆盖部分对应行为。大数据量下的合同可见范围预筛选仍可进一步改为数据库联表，当前仅限额后的可见结果返回客户端；红冲行查询已按原票行过滤。

演示票据生成早于补充逐行配置版本快照的代码，历史缺失字段显示“—”；不会用当前配置版本倒填旧票。以后新生成的票据逐行保留配置版本和授权人。
