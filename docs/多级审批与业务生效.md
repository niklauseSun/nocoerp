# 多级审批与业务生效

在“审批流程 → 审批配置”按项目选择新签合同、账单发布或采购申请，启用审批并配置 1–5 个顺序层级，每级可选多名候选人。每级任意一人通过即可进入下一级，全部通过才执行业务生效。申请人不能审批自己的申请；停用或无对应项目业务审批权限的人员会被排除，每级必须至少有一名有效候选人。

从业务单据的“审批流程”卡片提交，填写申请说明。在审批中心可查看“待我审批”“我提交的”及全部可见单据，按业务、状态、编号筛选。详情显示提交业务摘要、冻结层级、当前状态、可执行操作及处理历史。通过、驳回和取消均需说明并确认。

首次提交冻结配置。驳回后可修改单据并重新提交，从第一级重新审批；沿用原配置，生成新轮次和新的单据快照。配置更改只影响新申请。若原审批人不可用，有取消权限的管理员可取消申请，保留历史后重新提交以采用当前配置。

| 业务     | 全部通过前                                 | 最后一级通过后                       |
| -------- | ------------------------------------------ | ------------------------------------ |
| 新签合同 | 草稿，不占用资产，不可押金收取、出账或结算 | 合同生效、资产绑定、建立租赁台账     |
| 账单发布 | 草稿，不形成可核销应收                     | 发布应收，可统一收银、核销或抵扣押金 |
| 采购申请 | 审批中，不可转单                           | 申请审批通过，可转采购订单           |

审批中的源单据禁止直接修改，原账单发布、采购提交及审批接口同样受流程约束。最后一级通过与业务操作在同一事务执行：资产不可用、版本变化或业务校验失败时，审批意见和业务变化一起回滚。重复请求不会重复处理，并发处理同一层级只有一个成功。已有生效合同、已发布账单和已通过采购申请保留原状态；本次配置未覆盖续租和退租审批。

权限包含页面访问以及项目范围内的查看、配置、提交、审批、取消，并同时检查合同、账单或采购原有业务权限。配置人员不自动获得审批资格。演示没有真实付款、签约或外部消息。
