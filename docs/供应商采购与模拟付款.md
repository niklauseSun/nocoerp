# 供应商采购与模拟付款

入口为“供应商采购”，包含供应商、采购申请、订单、收货验收、付款和采购财务台账。费用台账也可进入采购财务台账；工单详情可发起和查看关联采购。

供应商按项目登记，支持联系人、供货范围、信用代码、资质有效期和停用恢复。采购申请选择资产，可关联同资产的未结束工单，填写需求日期、理由和物料清单。申请提交后批准或退回修改，批准后选择同项目供应商转一张采购订单。订单草稿可议价，价格不能超过批准的预算；确认下单后固定明细。

收货支持分批。到货数量、合格数量、不合格说明分别登记，只有审核通过的合格数量计入应付。草稿与待审核收货预占合格数量，避免重复验收；取消草稿释放预占。物料未验收齐全时，关联维修工单不能完工或关闭；全部验收后允许继续维修验收，即使供应商还有未付尾款。

付款只登记模拟凭证，支持分次，不得超付，不支持预付款。付款凭证号项目内唯一。登记错误可全额冲销，原记录和凭证保留，台账新增冲销流水；已结清订单重新打开。全部验收、净付款等于订单额后可结清。

采购台账按项目记录应付成本，不进入商户费用结算，不重复加到工单手工成本。所有金额以整数分计算：

- 已验收应付 = 审核通过的合格数量 × 订单单价之和。
- 净付款 = 模拟付款登记之和 − 已冲销付款之和。
- 剩余应付 = 已验收应付 − 净付款。
- 财务流水的正金额结合“验收确认应付 / 模拟付款 / 付款冲销”类型解释，汇总覆盖全部有权查看的记录，不随当前页筛选缩小。

## 权限与验证

页面授权与业务动作分别配置。业务资源为 hyl.procurement，按项目资产范围授权；供应商项目与报修来源仍须单独可读。付款与财务流水需要 financeRead，登记和冲销还需各自动作权限。系统不会为普通角色自动扩大授权。

tests/procurement 覆盖迁移 up/down、输入边界、完整流程、未登录与无权限、工单来源隔离、重复请求、超付阻止、并发付款冲突、采购表单验证和组合输入搜索；tests/repairs 回归现有工单行为。浏览器已跑通主流程和本地财务入口。真实移动端、原生中文输入法、其他外观预设以及真实外部付款不在本轮已验证范围内。

最终回归为 31 项测试、8 个文件通过，客户端与服务端类型检查通过；受影响文件 lint 无错误（4 项非阻断提示）。独立页面验收提出的 7 项问题均已修复并复查，包括来源加载错误恢复、关联记录同步刷新、工单采购预览、具体字段校验和记录提示、排序方向及下一步操作选择。另实际验证了供应商停用、具名提示和恢复启用。
