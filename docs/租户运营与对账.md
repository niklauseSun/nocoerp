# 租户运营与对账

## 2026-10-20 补齐结果

已按用户确认的设计实现中文界面，使用既有组件库；复杂流程采用独立覆盖页，简单操作采用路由弹窗。

- **现金收缴率**：有效现金核销÷当前已确认应收，排除押金抵扣、未分配预收及冲销；另列含押金的核销率。零分母显示 —。按月筛选不伪造历史应收。它反映登记台账，实际到账须对账确认。
- **外部流水对账**：UTF-8 CSV 上传、明确列映射、元/分及收入支出方向配置、预览后提交；有错整批不可导入。选中唯一候选批量确认，逐项显示结果；差异结论追加留痕。跨登记月份按业务日期核对，不通过匹配制造现金或修改原账单。
- **结算批次**：按项目、月份与月/半月周期预览，最多选30份合同；报送未齐/未审核及周期未结束禁止生成。可生成、复核选中项和仅重试失败项；保留每次结果。批次生成及进程中断恢复以来源项幂等。复核后仍须原结算确认，付款仍是登记线下付款。
- **转账准备清单**：按已确认且尚有余额的结算导出 XLSX；部分付款扣减余额，无完整收款资料标记阻止付款。导出重验源权限，不是真实付款凭证。
- **租户服务**：公告/政策草稿、发布、已读签收、撤回；投诉/建议提交、受理、截止日、回复、关闭、一次反馈。内容与事件留痕，租户只访问自己商户的可见记录。站内待办复用现有消息基础设施及个人订阅。
- **外部接入**：展示支付、开票、平台流水、小程序准备条件及本地 TEST 自检历史。未保存服务商密钥、未调用真实支付/税务接口、未发布小程序；H5 工作台与原业务模块提供现有入口。自检通过只证明本地契约，不代表远端联调成功。

新增管理能力使用独立权限 `hyl.tenantService/manage`、`hyl.integrationTesting/run`，不自动扩大真实岗位；批次继续使用原结算/合同/商户/资产来源权限。

设计已获用户确认。小调整：单一“打开”行操作使用文字按钮；批次内增加可返回同一批次、保留筛选的合同/结算来源详情，结算动作复用原业务 API。未改变主流程或支付边界。

## 日常操作

1. 在报送完整性里选月份，进入营业报送补报/审核。未报表示尚无记录；渠道齐全与否仍须核对当日实际业务，系统不凭空推定未配置的渠道。
2. 在结算交付里进入原结算单复核、线上确认或财务登记线下确认、登记线下付款；PDF/XLSX用于交付对账。
3. 欠费清单进入原账单/收款台账登记核销，跟进备注只记沟通过程。账龄基于业务到期日与当前上海日期，不会因切换历史月份变成历史余额。
4. 消息偏好里的「账单、结算确认与到期跟进」开启后，复用现有站内待办扫描：到期/逾期账单、待确认且可操作的结算，以及本人登记的到期跟进。最新跟进日期取代同来源的旧跟进，已结清账单不再催缴。不自动开启订阅，不接短信/邮件。
5. 外部流水先使用页面下载的 TEST 样例熟悉格式。导入后核对候选，再确认；找不到对应内部记录时先查原始台账，不用对账制造收款记录。

## 文件和银行数据边界

- 凭证每个10MB以内，校验真实 PDF/图片内容；存储复用官方 File Repository，下载为私密流。附件追加保留上传人和时间，不提供覆盖或删除历史凭证。新建报送先保存，再进详情上传；原凭证说明仍需填写。
- Excel 单元格作为文本保存金额和外部编号，避免超长数字精度丢失和公式注入。PDF通过系统中文字体渲染，生产环境须有中文字体；不是税务发票。
- 外部原始账单只向导入人展示；新的「外部流水对账/导入账单」权限单独授予。不自动扩大现有财务角色。确认匹配时重新取得财务与原资金来源权限；撤权后不可通过匹配记录继续读取源数据。
- 本轮不直接连接银行、支付平台、税务或真实转账。CSV是导入协议，后续拿到脱敏银行/平台原单再增加对应字段映射。
