# 巡检安保保洁与异常整改

入口：[巡检安保保洁](http://127.0.0.1:13000/main/inspections/tasks)。本模块统一管理巡检、安保、保洁三类业务，详情展示状态、可执行操作和历史。

## 使用流程

1. 新建计划：选择 1–20 个资产、执行人、起止日期、执行频率和 1–20 项检查标准。草稿或暂停时可编辑，启用后可暂停；草稿或暂停时可归档。
2. 生成任务：系统每 5 分钟按上海时区检查启用计划，也可指定已到期日期补生成。每天、每周、每月均以开始日期为锚点；月末不足同日时取当月最后一天。同一计划、资产、日期只能生成一个任务。
3. 执行任务：当前执行人开始执行，逐项记录正常或不适用；不适用必须填写原因。允许暂存部分检查结果，全部检查项有结论后才可提交审核。
4. 上报异常：选择检查项、严重程度、异常描述、现场说明、整改人及期限。系统同时创建异常单并把检查结果标记为异常，已登记异常不能改成正常来抹去问题。
5. 直接整改：当前整改人提交整改说明和依据，复查人可退回再次整改，或通过复查关闭异常。
6. 转报修：拥有巡检管理和报修权限的人员可将异常转为工单，沿用原资产和问题描述。完成派单、处理、验收和关闭后，才能提交异常整改。撤销工单不算修复，可重新转报修。
7. 完成任务：任务审核通过前，所有异常必须关闭。工单关闭不会自动关闭异常，也不会自动完成任务。

计划修改只影响后续任务。已生成任务保留当时的资产、检查项和执行人快照。指派、整改、复查、状态转换及操作人均有历史记录。

## 联动与权限

资产详情提供任务和异常预览及完整列表；异常可在原页面进入报修处理，工单详情提供关联异常的只读入口。关联记录仍需相应读取权限。

页面权限为 `hyl-inspections`，业务权限为 `hyl.inspections` 的 `read/manage/execute/rectify/review`。业务范围与资产读取范围取交集；执行与提交整改还要求当前指派人。定时生成使用计划创建人当前权限，创建人或执行人停用、权限不足、资产停用等问题会使该次调度记录失败。调度开关及运行历史另外需要 Scheduler 页面权限。

自动调度每批最多处理 5 个计划、100 个任务引用，每个计划最多推进 31 个日历日。使用轮转顺序避免失败计划长期阻塞其他计划，日期进度和任务唯一键持久化，后续运行继续补齐。当前沿用本机进程内 Scheduler；多进程部署需另行验证调度适配器。
